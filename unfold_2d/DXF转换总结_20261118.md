# DXF 转换总结（2026-11-18）

## 一、这个代码是干什么的

`make_dxf.py` 是 **2D 展开布局转 DXF 工程图**的独立生成器：读 2D 展开的
`layout.json`（与网页版查看器同一份几何、同一批标签），输出 CAD 能打开的
DXF（R2000，毫米）＋配套 Excel。它只负责“转 DXF”这一步，不做 3D 提取、不做
展开布局——布局由 `unfold_2d_v6p1.py` 等产出，本脚本只读布局、不改布局。

用法：

```text
make_dxf.py <layout.json> <out.dxf> [--excel <out.xlsx>]
```

依赖：plain python3＋ezdxf（不在系统 Python 里时用 `~/workspace/.pylibs` 兜底）。

## 三、现在是什么样子

- 6 图层，每块独立一层：TUBES(7) 管子、CONNECTOR(1)、NODE(5)、FORK(30)、LENGTH(3)、SEGMENT(2)。冻住一层，那一类整个消失。
- 5 个块定义：
  - CONNECTOR（圆 r=5.0＋10 个属性）：TAG=编号，NAME=真名短名，其余 8 个留空；只显示 NAME。
  - NODE（圆 r=3.0＋NAME/TYPE/CHANGED）：卡扣等节点，NAME=编号；只显示 NAME。
  - FORK（与 NODE 定义逐项相同，独立块与图层）：分支点，NAME=节点编号；只显示 NAME。
  - SEGMENT（管子的长度块，每分支一个，放弧长中点线上）：L=3D 弧长，E1/E2=两端节点；只显示 L。
  - LENGTH（只给多段分支的段放，放段中点法线下方 16mm）：L=段折线长，E1/E2=两端节点，PART_OF=na_nb；只显示 L。
- 管子是 TUBES 层普通多段线，不是块；旧纯文字长度标签已删。
- 地板（室内线束）实测：多段线 409/409、CONNECTOR 141、NODE 172、FORK 96、SEGMENT 409、LENGTH 151；误差 0.0000mm；ezdxf audit 0 错误；模型空间无 TEXT。
- 交付前验证（先写临时文件→回读核对→通过才落盘，失败不写盘、退出码 1）：图层、块定义（含显示标记）、多段线逐点、INSERT 数量/位置/属性值/显示标记、audit。

## 四、为路由准备的命名规则

目标：以后通过线段（SEGMENT）与端点（E1/E2）的名字，算任意两个连接器之间的路径长度。

- 节点名就是路由标识：连接器 CONxx、卡扣 CLPxx、分支点 BNxx；管子的 E1/E2 用节点名。
- SEGMENT 的 818 个端点 100% 对得上节点名，管子级路由链是通的。
- 注意：只用管名做分支点名行不通——多分支196.1 一个名对应 16 个分支点，路由会串点（已实测，方案已否决）。

## 五、还没定的事 / 已知问题

1. **SEGMENT 块未核实**：源文件里没有 SEGMENT 块，定义按用户粘贴摘要做（4 个 ATTDEF＋TEXT '='，'=' 已删）。拿到带 SEGMENT 的源文件后须再核对一次。
2. **LENGTH 的 E1 与 L 字重叠**：E1 在 (3.9,0)，与 L 同基线只隔 3.9mm，L 是 4–5 位数字时 E1 印在字尾上。源文件定义本身带来的，要不要调等用户定。（注：E1 现已隐藏，图上看不见，只影响导属性表时的位置。）
3. **CONNECTOR 长真名穿线**：NAME 字高 5，长名字在密集区会穿过邻近管子。
4. **LENGTH 有 162 个端点指向已合并的过路点**（N01–N73 等，图上无对应节点，网页版也一样）：只影响段级追溯，不影响管子级路由。
5. IP 版新标准 DXF 用户尚未要求（之前跑通 90/90 的是旧标准版），他要再做。
